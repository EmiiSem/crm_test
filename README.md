# Мини-CRM «Объекты и задачи»

Небольшая CRM для строительной компании: постановщик ведёт объекты (стройки) и задачи, исполнитель берёт свои задачи в работу и сдаёт на проверку. Вход по почте и паролю. Права проверяет база Supabase, а не только кнопки на экране.

Объяснение для руководителя, без технических терминов: [для-руководителя.md](для-руководителя.md).

## Запуск

Нужны Node.js 20+ и проект Supabase.

```bash
npm install
copy .env.example .env
```

В `.env` заполните адрес проекта, publishable key и строку подключения Postgres. Пароль базы и пароли сотрудников в git не попадают: файл `.env` указан в `.gitignore`. В сборку сайта Vite кладёт только переменные с префиксом `VITE_`. Строку `DATABASE_URL` туда не добавляйте и на хостинг не переносите.

На бесплатном тарифе прямой хост `db.<project>.supabase.co` часто доступен только по IPv6. Для миграций берите **Session pooler** из Supabase → Connect: пользователь `postgres.<project-ref>`, порт `5432`.

```bash
npm run db:bootstrap
npm run dev
```

`db:bootstrap` применяет миграции из `supabase/migrations`, создаёт трёх сотрудников и демо-данные: 3 объекта и 6 задач во всех статусах. Повторный запуск обновляет этих сотрудников и заново заполняет демо-объекты. `npm run db:reset` сначала удаляет таблицы CRM и применяет всё заново.

Приложение: [http://localhost:5173](http://localhost:5173).

Почты сотрудников записаны в `.env` (`TEST_*_EMAIL`). Пароли тоже там. В репозитории их нет.

Регистрация на сайте выключена в настройках проекта. Нового сотрудника через сайт завести нельзя: учётки и роли создаёт `npm run db:bootstrap`. Сам человек свою роль выбрать не может.

## Публикация

Подойдёт Vercel или Netlify. Сборка: `npm run build`, каталог `dist`, команда `npm run build`. В переменных окружения хостинга только:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

`DATABASE_URL` и ключ `service_role` на хостинг не класть. Их нет и во фронтенде.

## Как устроена защита

Сайт не хранит данные у себя. Он спрашивает облачную базу от имени вошедшего человека.

Постановщик видит все стройки и все задачи. Он создаёт и меняет объекты и задачи, назначает исполнителя, принимает работу или возвращает её на доработку. Вернуть на доработку без комментария нельзя.

Исполнитель видит только свои задачи и только те стройки, где такая задача есть. Чужую задачу он не откроет, даже если подставит её номер в адрес страницы: для него этой строки в базе нет. Текст чужой задачи он тоже не изменит. Взять в работу и отправить на проверку можно только свою задачу и только по цепочке: новая → в работе → на проверке. Из «на проверке» он не может ни принять задачу, ни вернуть её себе другим путём. После доработки он снова переводит задачу в работу.

Кнопки на экране повторяют эти правила, но решающим является запрет в базе. Если отправить запрос мимо сайта, база ответит отказ. Сменить статус «прыжком», например из «новой» сразу в «принята», нельзя: разрешённые шаги записаны в базе. История пишется сама в момент смены статуса: кто, когда, из какого статуса в какой и комментарий. Добавить туда запись, поправить её или стереть отдельным запросом нельзя. История исчезает только вместе с задачей, если постановщик эту задачу удаляет.

Ключ, который лежит в сайте, публичный. Он не даёт прав администратора. Каждому вошедшему база открывает только его строки.

## Решения, где в задании был выбор

- Принять задачу или вернуть на доработку может любой постановщик, не только автор задачи.
- Исполнителем можно назначить только сотрудника с ролью «исполнитель».
- Комментарий обязателен только при возврате на доработку. В остальных переходах его можно оставить, и тогда он попадёт в историю.
- Постановщик может менять название, описание, объект и исполнителя в любом статусе. Статус из формы редактирования не меняется.
- Описание задачи можно оставить пустым.
- Удаление объекта удаляет его задачи. Удаление задачи удаляет её историю. Отдельного удаления истории нет.
- На карточке объекта исполнитель видит только свои задачи.
- Одна роль на человека. Сотрудник сам себе роль не меняет.
- Свой сервер и Docker не используются: данные в Supabase, сайт — статические файлы.

## Что не входило в объём

Письма и уведомления, вложения файлов, смена пароля на сайте, постраничные списки, одновременное обновление экрана без перезагрузки.
